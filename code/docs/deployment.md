# Deployment Guide

## Overview

The 1757-RPG monorepo deploys as three services:

| Service | Platform | Method |
|---|---|---|
| **API** (`apps/api`) | Render | Docker image via `render.yaml` |
| **Web** (`apps/web`) | Vercel | `vercel --prod` from CI |
| **Admin** (`apps/admin`) | Vercel | Manual or CI deploy |

## Production Environment Variables

Set these in the Render dashboard (API) and Vercel dashboard (Web/Admin):

| Variable | Where | Notes |
|---|---|---|
| `DATABASE_URL` | Render | Neon pooled connection (`*-pooler.*`) |
| `DIRECT_URL` | Render | Neon direct connection (for Prisma migrations) |
| `BETTER_AUTH_SECRET` | Render | Auto-generated by `render.yaml` |
| `BETTER_AUTH_URL` | Render | Full API URL (e.g. `https://api.example.com`) |
| `WEB_URL` | Render | Web client origin for CORS |
| `ADMIN_URL` | Render | Admin console origin for CORS |
| `REDIS_URL` | Render | Upstash or Render Redis; omit for memory fallback |
| `NODE_ENV` | Render | Must be `production` |
| `PORT` | Render | `3001` (Render default) |
| `COOKIE_DOMAIN` | Render | `.yourdomain.com` for cross-subdomain cookies |
| `NEXT_PUBLIC_API_URL` | Vercel | API URL for client-side fetch |
| `NEXT_PUBLIC_WS_URL` | Vercel | API URL for Socket.io |

## Render Deployment

### Automatic (via render.yaml)

1. Push `render.yaml` to `main`.
2. In the Render dashboard, click **New → Blueprint** and select the repo.
3. Render reads `render.yaml` and provisions the `1757-api` service.
4. Fill in the `sync: false` variables in the dashboard.
5. Pushes to `main` auto-deploy via CI webhook.

### Manual

1. Create a **Web Service** on Render.
2. Set **Docker** as the environment.
3. Leave Root Directory empty, set Dockerfile Path to `./code/Dockerfile` and Docker Build Context to `./code`.
4. Set environment variables as listed above.
5. Configure the health check path to `/health`.

### Neon Postgres Connection Pooling

- Use the **pooled** connection string (`*-pooler.*`) as `DATABASE_URL`.
- Use the **direct** connection string as `DIRECT_URL` (for `prisma migrate` / `prisma db push`).
- Enable **connection pooling** in the Neon dashboard (PgBouncer mode).

### Redis Configuration

- **Upstash**: Paste the `rediss://` URL (TLS enabled) as `REDIS_URL`.
- **Render Redis**: Use the internal Redis URL from the Render dashboard.
- **Without Redis**: The API falls back to an in-memory snapshot store. Games will not survive a restart.

## Vercel Deployment

### Web App

```bash
# From CI (automatic)
vercel --prod --yes --token=$VERCEL_TOKEN

# Manual
cd apps/web
vercel --prod
```

Set `NEXT_PUBLIC_API_URL` and `NEXT_PUBLIC_WS_URL` in the Vercel project settings.

### Admin Console

Deploy `apps/admin` as a separate Vercel project with the same process.

## Docker Compose (Local Production Replica)

```bash
# Copy Docker env template
cp .env.docker .env

# Start the full stack
docker compose up -d

# Verify health
curl http://localhost:3001/health
```

Services started:
- **Postgres** (port 5432) with health check
- **Redis** (port 6379) with health check
- **API** (port 3001) with health check, depends on both

## Health Check

The `/health` endpoint returns:

```json
{
  "status": "ok",
  "uptimeSeconds": 3600,
  "timestamp": "2026-10-26T18:00:00.000Z",
  "services": {
    "database": "ok",
    "redis": "configured"
  },
  "memory": {
    "rssMb": 85,
    "heapUsedMb": 45
  }
}
```

- **200** — All services healthy.
- **503** — Database unreachable (`status: "degraded"`).

## Graceful Shutdown

The API handles `SIGTERM` and `SIGINT` signals:

1. Closes all Socket.io connections.
2. Drains in-flight HTTP requests via Fastify's close handler.
3. Exits cleanly.

This ensures zero-downtime deploys on Render (which sends `SIGTERM` before stopping the old instance).

## CI/CD Pipeline

See `.github/workflows/ci.yml`. The pipeline runs:

1. `pnpm install --frozen-lockfile`
2. `pnpm db:generate`
3. `pnpm typecheck`
4. `pnpm test`
5. `pnpm build`
6. Deploy API → Render (main only)
7. Deploy Web → Vercel (main only)

## Cold-Start Behaviour

On Render's free/starter plan, the API spins down after ~15 minutes of inactivity. The first request takes 15-30 seconds. The web client detects this and shows a "Waking server…" loading state.

## Rollback

1. Go to the Render dashboard → **Deploys** tab.
2. Click **Rollback** on the previous healthy deploy.
3. Render instantly switches traffic to the old image.

For Vercel, use the **Deployments** tab to promote a previous deployment.
